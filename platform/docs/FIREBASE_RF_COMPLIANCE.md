# Firebase и соответствие законам РФ

## 📋 Нормативная база

### 1. ФЗ-152 "О защите персональных данных"
**Требования:** Персональные данные граждан РФ должны храниться и обрабатываться на территории РФ.

**Решение TaskHive:**
- ✅ Используем Firebase Realtime Database с регионом `europe-west1` (Бельгия) для EU-граждан
- ✅ Для граждан РФ используем отдельный сервер в РФ (Yandex Cloud, Mail.ru Cloud)
- ✅ Персональные данные (ФИО, паспорт, ИНН) хранятся ТОЛЬКО на серверах в РФ
- ✅ Firebase используется только для push-токенов и неперсональных данных

### 2. ФСТЭК (Федеральная служба по техническому и экспортному контролю)
**Требования:** Криптография и защита данных должны соответствовать стандартам ФСТЭК.

**Решение TaskHive:**
- ✅ Используем TLS 1.3 для всех соединений
- ✅ Все данные зашифрованы в transit и at rest
- ✅ Ключи шифрования хранятся в защищённом хранилище (AWS KMS, Yandex KMS)
- ✅ Регулярные аудиты безопасности и penetration testing

### 3. ФЗ-54 "О защите детей от информации, причиняющей вред их здоровью"
**Требования:** Возрастная верификация для пользователей младше 18 лет.

**Решение TaskHive:**
- ✅ Проверка возраста при регистрации (18+)
- ✅ Согласие родителей для пользователей 14-18 лет
- ✅ Ограничение контента для несовершеннолетних

### 4. ФЗ-38 "Об информации, информационных технологиях и защите информации"
**Требования:** Защита критичной информации и уведомление об утечках.

**Решение TaskHive:**
- ✅ Система мониторинга и логирования всех операций
- ✅ Уведомление пользователей при подозрении на утечку (в течение 24 часов)
- ✅ Резервные копии данных в защищённом хранилище

## 📝 Система согласия пользователя

### 1. Первоначальное согласие
При первом запуске приложения пользователь видит:

```
┌────────────────────────────────┐
│ Разрешить push-уведомления?    │
├────────────────────────────────┤
│ TaskHive отправляет уведомления│
│ о новых заказах, сообщениях и  │
│ выплатах. Ваши данные          │
│ защищены и не передаются       │
│ третьим лицам.                 │
│                                │
│ [Подробнее] [Отклонить] [OK]   │
└────────────────────────────────┘
```

### 2. Хранение согласия
```sql
CREATE TABLE push_consent (
  id INT PRIMARY KEY,
  userId INT NOT NULL,
  consentGiven BOOLEAN DEFAULT FALSE,
  consentDate TIMESTAMP,
  consentVersion VARCHAR(10),
  ipAddress VARCHAR(45),
  userAgent TEXT,
  revokedAt TIMESTAMP,
  FOREIGN KEY (userId) REFERENCES users(id)
);
```

### 3. Управление согласием
- Пользователь может отозвать согласие в любой момент
- Уведомление об отзыве согласия отправляется на email
- Все push-токены удаляются в течение 1 часа
- История согласия хранится 3 года (для аудита)

## 🛡️ Защита данных

### Шифрование
- **In Transit:** TLS 1.3 (минимум 256-bit)
- **At Rest:** AES-256 для персональных данных
- **Key Management:** AWS KMS / Yandex KMS (HSM)

### Доступ
- **Role-Based Access Control (RBAC)** для сотрудников
- **Multi-Factor Authentication (MFA)** обязательна
- **Audit Logging** всех операций с данными
- **IP Whitelisting** для критичных операций

### Мониторинг
- **Real-time Monitoring** с Datadog/Sentry
- **Intrusion Detection System (IDS)** для выявления атак
- **DDoS Protection** с Cloudflare/Yandex.DDoS
- **WAF (Web Application Firewall)** для защиты от OWASP Top 10
